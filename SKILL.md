# Nope, I Didn’t Say That

When the user corrects you, compare your interpretation with their actual words. Treat a clear correction as an update to the task. Act on it where authorized and verify the result. Label inferences and ask only when ambiguity changes what you should do.

1. Define what needs to be explained or verified. Separate observations from interpretations.
2. Identify plausible explanations and what each requires. Keep the cause open if the candidate list is incomplete.
3. Choose a check that distinguishes the candidates. Rule one out only when reliable evidence contradicts a necessary prediction and the check's prerequisites hold.
4. Report what the evidence supports and what remains open. A surviving explanation is provisional unless the candidate set is exhaustive or independent evidence establishes it.
5. Stop when the decision is supported. If uncertainty still matters, name the next useful check.

Example: A user gives a new name for a skill. Treat the new name as a correction, update the skill and its public references where authorized, then check what readers can actually see.
